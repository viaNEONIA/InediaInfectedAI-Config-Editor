## 3. 期待仕様（受け入れ基準）

### 3.1 基本動作

1. 初回起動は同梱された公式初期設定から開始する。ブラウザ保存データを無断で自動復元しない。
2. 「JSONを開く」で既存JSONを読み込み、画面に反映する。
3. 数値・文字列・0/1設定を編集できる。値の型を不用意に変更しない。
4. 設定変更をブラウザへ自動保存できる。「設定を復元」で明示的に復元できる。
5. 「公式初期設定に戻す」で同梱初期値に戻る。意図せぬブラウザ保存データへの再上書きに注意する。
6. 「設定を保存」を押すと現在の編集内容を `InediaInfectedAIConfig.json` として**ダウンロード**する。
7. 出力JSONが構文的に正しく、読み込み直して同じデータを復元できる。
8. 未知のキー・追加キー・配列・入れ子のオブジェクトを、読込→編集→保存で保持する。

### 3.2 最優先：対象別オーバーライド

以下のような `all` を持つオブジェクトは、`all` 以外の対象をUIから追加・編集・削除できること。

```json
"SpeedLimitInCalmMode": {
  "all": 3.0,
  "ZmbM__Runner_Base": 2.1,
  "ZmbF_Runner_Base": 2.1,
  "highstr": 3.0
}
```

**確認対象**：`SpeedLimitInCalmMode`、`SpeedNoLimitsFromDistanceMeters`、および同じ構造を持つ他の設定。

- 「対象を追加」操作が画面に表示され、実際に押せる。
- 対象名を任意入力できる。`ZmbM__Runner_Base` の**アンダースコア2個**も保持する。
- 数値は小数を保持し、`0` も正しく受け付ける。
- 追加後にUIへ即時反映される。再描画で入力欄が消えない。
- 同名キーの重複を拒否する。空文字の対象名を拒否する。
- `all` は変更可能、ただし削除不可。
- 追加対象の値を後から変更でき、対象を削除できる。
- JSONダウンロード後も追加対象が存在する。
- JSON再読込、ブラウザ保存→復元でも追加対象が保持される。
- 対象名を変更する場合は元キーが残らず、値が失われない。

**重要な過去の不具合**：v7/v8では後から実行される描画補助処理が対象別編集UIを消す問題が報告された。v9では旧処理を除去したと報告されているが、実機・ブラウザ検証は未確認。DOM再描画・イベントハンドラー・タイミング依存を重点点検する。

### 3.3 リスト編集

- Wikiでクラス名やアイテム名の追加例がある設定は、配列の各要素を編集できる。
- 例示された「Ghillie Hood」のような名称をUIから追加・変更・削除できる。
- 配列が空の場合も項目追加できる。
- 同じ内容の配列が複数存在しても、編集対象のパスを取り違えない。
- リストUIと生JSON編集欄が併存する場合、どちらを編集しても同期し、古い値で上書きされない。
- オブジェクト配列・複雑な構造は、壊さず保存できる。

### 3.4 日本語説明

- 元の英語キー名は必ず確認できる。
- 主要設定には日本語ラベル・説明・単位を表示する。
- Wikiで確認できない意味や単位は「未確認」とし、推測で確定説明をしない。
- 検索では英語キーと日本語ラベルの双方を扱えることが望ましい。

## 4. 重点テスト手順

| ID | 操作 | 合格条件 |
|---|---|---|
| T01 | HTMLを新規ブラウザで開く | 公式初期値が表示される |

| T03 | `ZmbM__Runner_Base` = `2.1` を追加 | 追加行が表示される |

| T06 | `SpeedNoLimitsFromDistanceMeters` にも対象追加 | 同様に編集できる |
| T07 | `highstr` の値を変更・対象を削除 | UIと内部データが一致する |
| T08 | 「設定を保存」を押す | JSONファイルがダウンロードされる |
| T09 | ダウンロードしたJSONを開く | 追加対象・数値が一致する |
| T10 | ブラウザ保存→復元 | 対象別設定が復元される |
| T11 | 外部JSON読込→保存 | 未知キーを含め欠落がない |
| T12 | リストへアイテム名を追加・削除 | ダウンロードJSONに反映される |
| T13 | 空配列・重複配列・不正数値・空の対象名 | 破損や誤更新が起きない |
| T14 | 公式初期値へ戻す | 初期値へ戻り、UIも同期する |
| T15 | Chrome/Edgeの通常操作・ページ再読込 | JS例外や意図しない自動復元がない |

## 5. コードレビュー重点項目

- `render()` の多重ラップ、`setTimeout` による後付けDOM処理、旧機能によるUI削除の有無。
- 編集対象をラベル文字列やJSON値の一致で探していないか。**設定の完全パス**で識別すること。
- 値更新時にUI表示・内部`data`・`localStorage`・出力JSONが一致するか。
- 数値入力の空欄、`NaN`、`Infinity`、負数、小数、`0`の処理。
- 同名対象の追加・リネーム・削除と`all`保護。
- HTMLへの任意文字列表示にXSS対策があるか。ローカルJSONは信頼済みと決めつけない。
- Blobダウンロード、Object URLの解放、ファイル名、UTF-8、日本語文字列。
- 公式初期設定とユーザーの編集済みデータの区別。
- `localStorage`が無効な環境での例外処理。
- JSONを読み込んだだけで既存設定が消えないか。
- 対応ブラウザの互換性、オフライン動作、外部依存の有無。

## 6. 修正方針

1. **現行v9を基準に修正**。新規アプリとして作り直さない。
2. 修正前に実装機能一覧と再現した不具合を記録する。
